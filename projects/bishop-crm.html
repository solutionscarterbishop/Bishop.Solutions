Overview

Bishop CRM is the operational spine of an insurance brokerage. It handles the entire agent workday — the contact record, the pipeline stage, the phone call, the follow-up message, the meeting, the commission entry, and the report at the end of the week. It exists because the tools most agents use are a patchwork of narrow SaaS subscriptions that don't quite fit any of them.

Problem

Agents are asked to be salespeople, compliance officers, project managers, and analysts at the same time. The traditional stack (a generic CRM plus a dialer plus a messaging tool plus a calendar plus a spreadsheet for commissions) forces context switching, creates data drift, and makes compliance a memory exercise. Every hour spent stitching tools together is an hour not spent with a client.

Approach

Start from the agent's day, not the software category. Every screen answers a question the agent actually asks in real life: Who am I calling next? What did we last talk about? Was that outreach compliant? Did the application close? Did I get paid on it? The platform is opinionated where opinion helps and configurable where every brokerage genuinely differs.

Architecture

Multi-tenant web application built around a normalized contact model and an event-sourced activity log. Communications are gated through compliance and consent checks before hitting any transport layer. Pipelines, commissions, and reporting run against a materialized read model so day-to-day performance stays fast even as the activity log grows.

Technology

Modern web stack with a strongly typed application layer, relational database, message queue for outbound communications, and a real-time layer for the unified inbox and dialer. Third-party telephony and messaging carriers are integrated behind an internal abstraction so a compliance change or provider change never leaks into product code.

Lessons

  • Compliance is a first-class feature. If TCPA rules aren't wired into the dialer and messaging paths at the model level, no amount of training will keep an agent safe.
  • Speed matters more than surface area. Agents keep the tool open all day; every latency hit is a compounding tax.
  • Data model beats interface. Getting the contact and activity schemas right in the first version made every later feature cheaper.

Impact

Replaced a stack of three separate paid tools per seat with a single system that the operator actually enjoys using. Conversation follow-through improved because there was finally one source of truth for every touchpoint, and commission visibility went from "the spreadsheet Susan owns" to a live dashboard.

Future direction

Deeper carrier integrations, sharper reporting on cohorted retention, and an "assistant" layer that drafts the right next message given the state of the pipeline. The goal remains the same: keep the agent in front of the client and out of the software.
